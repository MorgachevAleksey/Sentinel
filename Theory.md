# Ключевые понятия

IoC - инверсия управления
Не класс управляет зависимостями, а внешний контейнер за него
Не класс решает какая будет реализация зависимости (что придет в аргумент конструктора)

DI - конкретная реализация IoC 
Зависимость внедряется извне - через конструктор (можно так же через поле/setter, но это кринжик)
Дает слабую связанность, упрощает тестирование, делает код гибким
    
Bean - обьект (обычный, просто живет внутри Spring-контейнера), которым управляет Spring-контейнер
- помечен аннотацией-стереотипом:  @Component, @Service, @Repository, @Controller, @RestController
- создан в методе с @Bean в @Configuration-классе

Spring при старте:
0) Создает ApplicationContext
1) Сканирует пакеты (@ComponentScan)
2) Находит классы с аннотациями
3) Создает их экземпляры
4) Внедряет зависимости (связывает их между собой)
5) Далее управляет их жизненным циклом

ApplicationContext - это сам Spring-контейнер, обьект внутри которого:
- храняться все бины
- настроены их связи
- работает механизм DI

Анотации-стереотипы - те же бины разница только семантическая (кроме @Repository - он еще включает трансляцию SQL-исключений)

# Практика

DI реализация 
1) Нужному классу прописывается поле инжектируемого класса
2) Инициализируется поле в конструкторе
А спринг сам найдет обьект нужного класса и передаст аргументом при создании Бина

Внешняя конфигурация
YAML (.yml) предпочтитительнее properties потому что:
- иерархичен
- читаемее
Достаточно поменять расширение конфигурационному файлу из коробки
Это реализация 12 factor app

Работа с БД
Hibernate
    Режим validate - исключительно проверка на соответсвия сущности схеме таблицы
Flyway - миграциями, версионно создает\модифицирует таблицы в БД
postgreSQL - реляционная (хранит данные в виде связанных таблиц) База Данных
Docer compose - контейнер
Реализация:
1) Задать режим работы Hibernate в YAML конфигурации
2) Подключить зависимости JPA\Hibernate, FlyWay, JDBC\postgreSQL
3) Создать Docker compose YAML в корне

# Аннотации 

- @PathVariable - извлекает значение x из пути (до ?) вида /something/{x}
- @RequestParam - звлекает параметры запроса (после ?) как ключ-значение
- @Value - простой способ прочитать значение из конфигурационного файла
- @ConfigurationProperties(prefix = "") - правильный:
    1) Прописывается в .yml
    2) Создается класс-конфиг (связывание имен для маппинга, геттеры\сеттеры обязательны(нужны для маппинга спрингом))
    3) Спринг сам маппит анотацией по префиксу
  На аннотации поддерживается валидация Spring
  Плюс подхода - мапится само + валидация на старте
- @ConfigurationPropertiesScan - !подключение конфигурации - иначе не сработает
- @Valid - пишется над сложным (например являющимя классом) полем, аргументом или коллекцией (включатель на уровне полей\аргументов\коллекций - проводник внутрь)
- @Validated - пишется над классом, которому нужно подключить проверку валидации (включатель на уровне класса)
